    Data¶

    Data is the union of file-only FileData and structured result types. All result types inherit from FileData and require provenance, which identifies the producing program and its optional version. When contained in a ProgramOutput, the concrete type depends on the requested CalcType.

    Standalone data objects hold scientific values and producer identity. They do not duplicate the calculation input; retain a ProgramOutput when you need that context.

    Empty data is valid for every scientific type. For an empty OptimizationData, final_structure and final_energy return None; structures and energies are empty collections. With frames, a failed final step still contributes its evaluated structure, and any available energy is retained. An unavailable energy is nan, independently of execution success.

    Frames: structures inside a calculation¶

    A Frame is one structure inside a larger calculation, with what was computed there: an optimizer step, an IRC point, an image of a path. It is a ProgramOutput without input_data (both build on OutputBase: success, logs, traceback, execution). The parent's input already holds the program, model, and keywords, so a frame keeps only its structure and results, a SinglePointData that is never None (empty, with the producing program's provenance, when nothing was computed). ProgramInput.from_spec(parent_spec, frame.structure) rebuilds a step's exact input; Frame.from_output(child_output) records a child calculation as a frame. Passing ProgramOutputs where frames are expected, or loading trajectories saved before frames existed, converts them, taking each step's structure from its input.

    Results that hold structures read the same way: structures, energies (nan where none was computed), to_xyz(), and save("x.xyz"). That holds for OptimizationData (one frame per step), PathData, PathOptimizationData (its final path), and ConformerSearchData (its conformers).

    PathData is a path of frames in order, with ts_index marking the transition state if there is one. For an IRC the frames run from the end of the reverse branch, through the transition state, to the end of the forward branch; for a chain (NEB, string) they are the images, endpoints included. forward_barrier and reverse_barrier are the transition state's energy above the first and last frames, in Hartree. PathOptimizationData.paths holds the path at every iteration, like an optimization's steps; final_path is the result.

    Fields are named after what they hold: frames (OptimizationData, PathData), paths (PathOptimizationData), points (ScanData, one constrained optimization per point), and conformers/rotamers (ConformerSearchData, frames sorted by energy). The former names OptimizationData.trajectory and ScanData.trajectory are still accepted when constructing or loading and readable as properties, with a FutureWarning. ConformerSearchData still accepts lists of structures with conformer_energies/rotamer_energies arrays, turning each into a frame, and keeps those arrays as properties.

    ScanData defaults to no points. Its structures preserves one entry per scan point, using None when a point has no optimization steps. XYZ export raises ValueError if a point lacks a final structure rather than silently omitting it.

    Array schemas describe the canonical nested JSON representation: vectors are one-dimensional, geometry/gradients/Hessians are matrices, and normal modes have three dimensions. Constructors continue to accept flat arrays where scientific shape validators can reshape them.

    qcdata.SinglePointData ¶

    The computed data from a single point calculation.

    Attributes:

    Name Type Description
    energy float | None

    The electronic energy of the structure in Hartrees.
    gradient SerializableMatrix | None

    The gradient of the structure in Hartrees/Bohr.
    hessian SerializableMatrix | None

    The hessian of the structure in Hartrees/Bohr^2.
    nuclear_repulsion_energy float | None

    The nuclear repulsion energy of the structure in Hartrees.
    wavefunction Wavefunction | None

    Wavefunction data from the calculation.
    freqs_wavenumber list[float]

    Harmonic vibrational frequencies in wavenumbers (cm^-1), negative for imaginary modes.
    normal_modes_cartesian SerializableTensor3D | None

    n_vibmodes x n_atoms x 3 array of normal modes, one per entry of freqs_wavenumber and in the same order. Each mode is a Cartesian displacement (not mass-weighted) scaled to unit length, in the input structure's frame and atom order; it is dimensionless. The sign of a mode is arbitrary. Multiplying a mode by the square root of each atom's mass and normalizing gives the eigenvector of the mass-weighted Hessian.
    gibbs_free_energy float | None

    Gibbs free energy (i.e. thermochemical analysis) in Hartrees of a system where translation / rotation / vibration degrees of freedom are approximated using ideal gas / rigid rotor / harmonic oscillator respectively.
    scf_dipole_moment list[float] | None

    The x, y, z component of the dipole moment of the structure in units of e a0 (NOT Debye!).
    atomic_charges SerializableVector | None

    Partial charge on each atom in units of e, ordered like the structure's atoms. The partitioning scheme (Mulliken, Lowdin, CM5, ...) is the program's; parsers record it in extras when it is not the program's default.
    point_charge_gradient SerializableMatrix | None

    n_charges x 3 gradient of the energy with respect to the positions of external point charges, in Hartrees/Bohr, ordered like the point charges given to the calculation (QM/MM electrostatic embedding).

    Selecting a scientific data type¶

    Use the shared get_data_type(calctype) lookup rather than maintaining a mapping in parsers or execution packages. It accepts either CalcType or its string value:

    from qcdata import get_data_type

results = get_data_type("optimization")(provenance={"program": "geometric"})

    File-only execution uses FileData directly. Unknown calculation types raise ValueError.
